# 图片 / 音频批量处理工具

基于 **FFmpeg** 的图片格式转换 / 压缩与音频封面 / 元数据批处理桌面工具。

## 运行环境

- PyQt6、PyQt6-Fluent-Widgets、PyQt6-Frameless-Window
- FFmpeg：优先使用 PATH 中的 `ffmpeg`，也可在界面里手动指定 `ffmpeg.exe`


## 功能

### 输入规则（A / B / C）

| 输入 | 行为 |
| --- | --- |
| **A：单个图片文件** | 在文件所在目录新建 `<文件名去掉后缀>_output` 文件夹，转换结果输出到其中，命名保持原文件名 + 新后缀 |
| **B：文件夹（不含子文件夹且含图片）** | 整批统一处理，在该文件夹下新建 `<文件夹名>_output` 子文件夹，结果整批合并输出，每个文件命名与源文件相同 |
| **C：文件夹（含子文件夹）** | 递归检查每个子文件夹，递归到所有“无子文件夹且含图片”的叶子目录，各叶子目录按 B 处理 |

说明：

- `*_output` 目录会被自动忽略，不会把上次的输出再当作输入，可通过“重复处理”开关切换设置；
- C 情况下，中间目录自身的直接图片文件不参与处理（遵循 A/B/C 规则）；
- 处理只产生新文件，**不会改动或删除任何源文件**。

### 输出位置（可切换）

- **自动模式（默认）**：单文件 → 在源文件旁生成 `<文件名>_output`；
  文件夹 → 在源文件夹下生成 `<文件夹名>_output`。
- **指定输出目录模式**：先选择一个输出根目录，之后每个批次仍输出到自己的 `<名称>_output` 子目录。

### 转换 / 压缩参数

- **目标格式**：保持原格式（仅重新编码压缩）、JPG、PNG、WebP、GIF、AVIF、BMP、TIFF；
  AVIF / GIF 是否可用取决于当前 ffmpeg 是否带对应编码器（程序会自动探测，不可用时下拉项置灰）。
- **质量**：1~100（默认 80），越大画质越好、文件越大。
  映射到各编码器参数：JPG → `q:v 2~31`；WebP → `quality`；AVIF → `crf 0~63`；
  GIF → 调色板颜色数 `32~256`（`palettegen` + `paletteuse` 量化）。
  PNG / BMP / TIFF 为无损编码，质量不适用（控件自动禁用）。
- **最长边**：按比例限制输出图片的最长边像素，`0` 表示不缩放（不放大）。
- **同名输出**：开关“覆盖已存在的输出文件”（默认开）。

### WebP ⇄ GIF 互转（含动画）

- **GIF 可作为输入**：`.gif` 已加入输入类型，选择或拖入 GIF 后：
  - 目标格式选 **WebP** → GIF 转 WebP；
  - 目标格式选 **GIF** → GIF 重新量化压缩（保持原格式时同理）。
- **WebP 转 GIF**：目标格式选 **GIF**，静态 WebP 与动画 WebP 都支持。
- **动画整段保留**：GIF / WebP 都是多帧动画格式，互转时保留全部帧
  （输出 GIF 用 `gif` 编码器 + 调色板量化；源为动画时输出 WebP 使用
  `libwebp_anim` 编码器），循环次数统一为无限循环。
- **单帧格式保护**：动画 GIF / WebP 转成 JPG / PNG / AVIF / BMP / TIFF 等
  单帧格式时只取第一帧，避免 ffmpeg 因“同名文件写入多帧”而直接失败。
- 输入规则（A / B / C）、输出位置与命名规则与其它格式完全一致。

### 音频处理 → 专辑批处理

边栏进入“音频处理”后，在主页点击“专辑批处理”入口进入。

- 输入一个**专辑根目录**，根目录下每个一级子文件夹视为一张专辑；
- 在专辑文件夹内递归查找音频与图片；
- 封面图片所在目录必须同时包含 `album.txt` 和 `artist.txt`：
  - `album.txt` 内容写入音频的 `album`（唱片集）属性；
  - `artist.txt` 内容写入 `artist`（参与创作的艺术家）属性，多个艺术家用空白分隔，写入时自动转换为分号分隔（如 `Alice Bob` → `Alice;Bob`）；
  - 音频原有 `title` 与 `#` 属性会被清空；不写入唱片集艺术家属性。
- 专辑内没有图片、有多张图片，或缺少 / 为空的 `album.txt`、`artist.txt` 时，跳过该专辑；
- 输出文件夹名为专辑文件夹名，放在每个音频实际所在的文件夹内；输出只产生新文件，**不会改动或删除任何源文件**；
- 同名输出：开关“覆盖已存在的输出文件”（默认开）。

示例结构：

```text
D:\Music\Root\A\Images\cover.jpg
D:\Music\Root\A\Images\album.txt
D:\Music\Root\A\Images\artist.txt
D:\Music\Root\A\Disc1\song1.mp3
D:\Music\Root\A\Disc2\song2.mp3
```

运行后生成：

```text
D:\Music\Root\A\Disc1\A\song1.mp3
D:\Music\Root\A\Disc2\A\song2.mp3
```

支持的音频扩展名：`.mp3`、`.m4a`、`.mp4`、`.aac`、`.flac`、`.ogg`、`.opus`、`.wav`、`.wma`、`.alac`。
支持的图片扩展名：`.jpg`、`.jpeg`、`.png`、`.webp`、`.bmp`。

注意：`.wav` 会输出为 `.mp3`（WAV 通常不适合嵌入封面图片），其他格式尽量保持原扩展名并复制原音频流。

### 音频处理 → 元数据编辑

在“音频处理”主页点击“元数据编辑”进入。基于 **ffprobe 读取 + ffmpeg 写入**（无需额外 Python 依赖）：

- **输入**：可多选音频文件，或导入一个文件夹；
- **字段选择**：下拉多选需要修改的元数据条目；
- **预览表格**：文本字段为可编辑文本框，**全部修改只在内存中，点击“确认修改”后才真正写入**；
- **统一操作**：点击列头（如“标题”）弹出“全部改为”小窗；点击封面单元格同样弹出封面小窗；点击格式单元格弹出格式转换小窗；
  - 作者支持 `name1;name2;name3` 分号分隔；
- **同名保护**：原地换扩展名时若目标文件已存在，不覆盖而是改用 `名称 (1).扩展名`；输出模式下同一批内的同名输出也会自动加序号；
- **mp3 统一写 ID3v2.3**（与图片模块 / 专辑批处理一致），Windows 资源管理器等能正常读到标签；

注意：`.wav` / `.aac` / `.ogg` / `.opus` 容器不支持内嵌封面（写入时自动忽略封面并记日志，OGG/OPUS 因此不作为“为 wav 添加封面时自动转换”的目标格式）；AAC(ADTS) 容器不保存元数据标签，目标为 `.aac` 时元数据修改会被忽略并记日志。

## `取消`与`停止`
- 按下取消立即中止；
- 按下结束处理当前批次，随后停止。

```
compress_images/
├── main.py              # 入口

│   ├── Core.py          # 图片 A/B/C 目录规则、批次构建、参数模型

    ├── AlbumWorker.py   # 专辑批处理后台线程
    ├── MetadataPage.py  # 元数据编辑页面

```

## 备注

- GIF 为 256 色调色板格式，色彩丰富的图片转 GIF 后可能出现色带或抖动噪点，这是 GIF 格式本身的限制，调高“质量”（颜色数）可缓解；
- 目标为“保持原格式”时，PNG/BMP/TIFF 等无损源只做无损重编码，压缩收益有限；
- 若 ffmpeg 输出 AVIF 的速度较慢（取决于编码器），这是 FFmpeg 编译版本的固有特性。
